# LAYOUT

Authoritative directory and locking convention for the issues store.
This file is the source of truth; anything elsewhere that disagrees with
this document is wrong.

## Directory layout

Issues live under `<PREFIX>/<ID>.md` from the store root. `PREFIX` is
the per-project namespace owner (e.g. `IM`, `RM`). `ID` is the full
`<PREFIX>-NNN` identifier. The directory under the store is
implementation, not identity: cross-references between issues continue
to resolve by ID, never by path.

```
issues-store/
  README.md
  LAYOUT.md
  INDEX.md
  ISSUE-TEMPLATE.md
  .gitignore
  .repos                 # tracked: project registry (basename:PREFIX, lex-sorted)
  .locks/                # gitignored
    INDEX.lock
  IM/
    IM-001.md
    INDEX.md
    .locks/              # gitignored
      IM-001.lock
  RM/
    RM-001.md
    INDEX.md
    .locks/              # gitignored
```

`INDEX.md` files (top-level and per-prefix) are generated by
`reindex-issues` from the issue files. `ISSUE-TEMPLATE.md` is the
default issue template; a per-prefix override may live at
`<PREFIX>/ISSUE-TEMPLATE.md` and takes precedence for issues created
under that prefix.

## Concurrency baseline (P2)

Multiple Claude Code sessions, humans, and future autonomous agents will
operate semi-parallel against this store. Conflicting writers to the
same issue are expected, not exceptional, so every writer implements
concurrency control from day one. The model is three-layered: every
mutating operation performs an atomic temp-file `rename(2)` in the same
directory as the target; every read-modify-write acquires a per-record
advisory lock (`fcntl.flock(LOCK_EX)`) on a sidecar lockfile held only
for the duration of the RMW; every write performs optimistic mtime and
sha verification at rename time and surfaces `concurrent-edit` (CLI
exit code 3) if any value has changed between read and write.

## .locks/ directories

Lockfiles live alongside their target files in per-prefix `.locks/`
subdirectories, plus a top-level `.locks/` for store-wide resources
such as `INDEX.lock`. Per-record locks are at
`<PREFIX>/.locks/<ID>.lock`; INDEX rebuilds serialize on
`.locks/INDEX.lock` against other reindex runs but do not block per-issue
writes. Lockfiles are ephemeral: the kernel releases them automatically
when a process exits, so no manual cleanup is needed. `.locks/`
directories are gitignored at every level via the top-level
`.gitignore`; the directories may exist on disk but their contents are
never tracked.

## Project registry (.repos)

`<store>/.repos` is the registry of projects that share this store.
Each line is `<basename>:<PREFIX>`, lex-sorted. Mutated only by
`init-issue-project`; consumed by `new-issue`, `reindex-issues`, and any
future tool that needs to resolve a repo to its prefix. A project's
local `.issues/.prefix` (when present) must agree with its registry
entry; consumers hard-fail on disagreement.
